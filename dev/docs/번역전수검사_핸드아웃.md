## 2. 남은 작업 (재개 절차)

### 준비 (payload 재생성 — 스크래치 디렉토리는 세션 휘발)
```bash
export PF2E_AUDIT_DIR=/tmp/pf2e-audit   # 감사 작업 디렉토리
mkdir -p $PF2E_AUDIT_DIR
cp /tmp/PF2e-publish/dev/tools/audit/broken_entities.json $PF2E_AUDIT_DIR/
cd /tmp/PF2e-publish/dev
node tools/audit/gen_payloads.js       # 11카테고리 items_* + repair 0-5 + rename + ui + csdata + name_index.json
node tools/audit/gen_creatures2.js     # creatures_* 279개(영문 정본 포함) — gen_payloads의 creatures를 대체
node tools/audit/gen_markup_scan.js    # repair 6-11(깨진 @표현식 47엔티티, 영문 포함 재생성 포함)
cp dev/tools/audit/out_partial/*.json $PF2E_AUDIT_DIR/out/   # 완료된 28배치 복원(재실행 방지)
```
⚠ gen_markup_scan 후 repair 6+ 배치에 desc_en 보강 스텝이 필요했음(이번 세션에선 별도 node 인라인으로 했음 — gen_markup_scan.js가 excerpt만 담으면 영문 첨부 로직을 확인할 것).

### 실행 (워크플로우)
- 템플릿: `dev/tools/audit/audit_workflow_template.js` — **CANON은 Force=역장으로 이미 정정됨**. 상단 `P` 상수를 `$PF2E_AUDIT_DIR`로, `FILES` 배열을 담당 배치 목록으로 교체.
- **args로 파일 목록을 넘기지 말 것**(Workflow args 문자열화 버그 — 이번 세션 실증). 반드시 스크립트에 리터럴 배열로.
- **분할 권장**: 워크플로우당 동시 슬롯 ~16개. 3분할 예시 = A(equipment 127+feats 113) / B(나머지 items+ui+csdata+repair+rename ~125) / C(creatures 279). `dev/tools/audit/split.json`에 분할 목록 저장돼 있음(28개 완료분 제외 상태).
- **페이스 실측**: 배치당 15~20분(영-한 전문 대조). 3분할 총 ~12h. 사용량 한도(session limit) 주의 — 한도로 죽은 배치는 결과 out파일이 없으므로 재실행 목록 = `payload에 있고 out에 없는 파일`.
- 완료 배치는 `$PF2E_AUDIT_DIR/out/<batch>.out.json`으로 쌓임. 실패해도 재실행하면 이어짐(멱등).

### 병합·검증

- 자동검증 내장: ① 마크업 골격(@표현식 스켈레톤 — 수정본에 새/변형 @expr 있으면 리젝트, 삭제는 허용) ② HTML 태그 멀티셋(±2 초과 리젝트) ③ 60%+ 대편집 경고 목록 ④ **termFilter — 초기 28배치가 구 CANON(힘)으로 작업돼 유입 시 힘 피해→역장 피해 자동 정정**.
- 리젝트 항목은 merge_report.json 보고 개별 판단(대부분 에이전트 마크업 실수 — 버리면 됨, 수량 많으면 해당 배치 재실행).

## 3. AI 에이전트 프롬프트 (정본 — audit_workflow_template.js에 내장)

배치 유형별 프롬프트는 템플릿 파일의 `itemsPrompt`/`creaturesPrompt`/`uiPrompt`/`csdataPrompt`/`repairPrompt`/`renamePrompt` 함수에 있음. 핵심 골격:

- **공통 CANON 블록**: 용어집.md의 표를 압축 수록(피해유형 Force **역장**, 기술 위협·사회, 숙련도 달인, 무방비/명중 굴림/재주/특성/랭크 …). **용어집.md 갱신 시 CANON 블록도 동기화할 것.**
- **공통 MARKUP 블록**: @UUID/@Damage/@Check/@Localize/@Template/@Embed 대괄호 내부 무수정·{라벨}만 한글 / `[[/r]]`·`[[/act]]` 골격 무수정(런타임이 렌더) / HTML 태그 구조 유지 / ⟬토큰⟟·� = 손상 → 영문 원문 기준 재구성 / 수치·주사위·DC·거리 영문 대조 최우선.
- **최소 수정 원칙**: 문제 없는 항목 출력 제외 / 전면 재번역은 총체적 오역만(reason 필수) / 확신 없으면 flags.
- **함정 명시**: «마스터» 문맥판단(사역마 주인·스승·masterwork·숙달 동사는 정당) / «특기»→재주는 Feat만, "N피트" 거리 불변 / 배경 카테고리 desc_en 없는 필드는 ko 품질만.
- **출력**: `$AUDIT/out/<batch>.out.json` 파일 Write(fixes/flags) + StructuredOutput 요약({checked,fixed,flagged,note}) — desc 대량을 return으로 넘기지 말 것(컨텍스트 폭발).

## 4. 함정·교훈 (이번 세션 실증 — 다음 세션 필독)

1. **Force=역장.** 용어집 파일도 틀릴 수 있다. 기계 치환 전 코퍼스 지배 표기와 3배+ 어긋나면 사용자 확인 먼저.
2. **Workflow args 문자열화 버그** — 배치 목록은 스크립트 리터럴로.
3. **세션 한도** — 대량 에이전트는 한도 리셋 직후 시작 권장. 한도로 죽으면 out파일 부재 = 재실행 대상 판별 기준.
4. **payload/스크래치 휘발** — 도구·완료 산출물은 repo(`dev/tools/audit/`)가 정본. payload는 재생성(수 초).
5. **agent가 payload 폴더에 잡파일 생성 가능**(`*.pretty.json` 등) — 배치 목록은 패턴 매칭 말고 저장된 목록 사용.
6. **문단전용 죽은 링크는 3종**: `-effects` 팩 @UUID + `journals.JournalEntry` @UUID + @Embed — enrichDesc가 이미 런타임 제거하므로 **에이전트가 desc에서 지울 필요 없음**(지워도 skelDiff가 삭제는 허용).
7. cs_monster.js 소비자는 Bestiary.html·Map.html — 수정 시 두 파일 `?v` 범프(bump_version이 처리하는지 확인).
8. 초기 28배치 out파일은 구 CANON(힘) — merge의 termFilter가 정정하므로 그대로 사용 가능.

### §4 추가 (2026-07-02 저녁, Lore 통일 작업에서 실증)
9. **파생 재빌드 후 반드시 `node tools/normalize_terms.mjs --apply` 재실행** — build_traits/build_system_terms 등은 PF2e-KR raw 라벨(포스 등)을 다시 가져와 정본화를 회귀시킨다(실측 35건 회귀). 근본 소스는 `data/overlay/_lang.ko.json`이므로 지속 회귀 항목은 _lang 값 자체를 정정.
10. **`build_effects.mjs`는 재실행 불가**(레거시 feat_db.js 소멸) — `effects_db.js`+`data/derived/effects_db.json`+`effects.json`은 이제 직접 편집 대상. 재주 이름을 바꾸면 **effects_db의 grant 대상명(target) 파리티 검증 필수**(이름 문자열로 참조하는 행 존재 — Lore 때 51건 일치 확인 후 통과).
11. **파생 줄수 급감 ≠ 데이터 손실** — 빌더 들여쓰기 차이로 diff가 −수천 줄 나올 수 있음. 문자열 개수/rows 수로 시맨틱 비교할 것(글로서리 1,612 strings 동일 사례).
12. **용어 통일 스윕은 `tools/sweep_lore.mjs` 패턴 재사용** — 보호 토큰(고유명) placeholder → 치환 → 복원. 한글엔 \b 워드바운더리가 안 먹으니 "X의 로어" 같은 변형은 별도 규칙. 통일 후: 파생 재빌드(7종+prereqs) → normalize --apply → build_glossary_index → 검증(예외 외 잔존 0).
